# Диагностические скрипты

Скрипты ищут формальные признаки, а не оценивают литературное качество.
Регулярное выражение не знает функции фразы, намерения автора и реакции
читателя.

## Запуск

```text
python3 tics.py   file.docx [--list] [--strict]
python3 ladder.py file.docx [--list] [--strict]
python3 range.py  file.docx [--list] [--strict]
```

- без флагов — агрегированный диагностический отчёт, код возврата 0;
- `--list` — показать найденные места для ручного просмотра;
- `--strict` — вернуть ненулевой код при выходе за исторические ориентиры.

Строгий режим нужен для воспроизводимого сравнения версий, а не для решения,
можно ли принять художественный текст.

## Ограничения

### `tics.py`

- названия осей описывают гипотезу;
- «пуант» определяется длиной и поверхностной грамматикой;
- «триада» определяется числом и длиной предложений, не их смыслом;
- регулярки пропускают перефразированные варианты и дают ложные совпадения;
- одна ось считается не больше одного раза на абзац, даже если конструкция
  повторилась внутри него;
- деление на трети не учитывает границы сцен.

### `ladder.py`

- любой абзац наррации разрывает серию;
- короткая серия может быть точным ритмом сцены;
- длинная реплика не является обязательной;
- показатель следует сравнивать по сценам, а не только по всей главе.

### `range.py`

- регистры определяются по ключевым словам;
- лексика тела не доказывает, что среда причинно участвует в сцене;
- `казалось` и `возможно` не доказывают содержательного сомнения;
- слова о попытке не доказывают, что физическое действие действительно
  не удалось;
- наблюдаемые минимумы старого корпуса не являются квотами.

## Правильная петля

1. Сначала прочитать текст и сформулировать подозрение.
2. Использовать скрипт, чтобы собрать похожие места.
3. Просмотреть каждую находку в сцене.
4. Исправлять только подтверждённые случаи.
5. Перечитать текст, не проверяя лишь изменение числа.
